# 프로테니스 · 랠리

테니스 레슨 예약 및 코치 주간 일정 관리 시연입니다. 로그인과 역할 검사는 서버에서 처리하고, 예약·출석 변경은 브라우저 안에 저장합니다. 실제 예약, 결제, 알림, Google Sheets 쓰기 기능은 없습니다.

## 로그인과 권한

- `/` → 로그인한 계정의 역할에 맞는 화면으로 이동합니다.
- `/login.html` → 이메일·비밀번호 로그인.
- `/coach.html` 및 코치 데이터·스크립트 → `coach` 역할만 접근 가능합니다.
- `/index.html` → `student` 역할만 접근 가능합니다. 코치는 직접 주소를 입력해도 403 응답을 받습니다.
- 역할은 서버 설정에서 결정하며, 로그인 요청으로 역할을 바꿀 수 없습니다.
- 세션은 서명된 HttpOnly/SameSite 쿠키이며 HTTPS에서는 Secure 속성을 사용합니다. 만료는 8시간입니다.
- 계정 삭제, 비밀번호 해시/역할 변경, AUTH_SECRET 교체 시 이전 세션이 거부됩니다. 로그아웃은 해당 브라우저 쿠키를 삭제합니다.
- 기본 계정·공용 비밀번호·회원가입은 없습니다. 설정이 없으면 로그인할 수 없습니다.

## 계정 설정과 로컬 실행

Node.js 24에서 프로젝트 폴더의 터미널을 열고 실행합니다.

```sh
npm run setup:auth
npm run dev
```

계정 설정 시 이메일, 표시 이름, 역할(기본 `coach`), 12자 이상 비밀번호를 입력합니다. 비밀번호 입력은 숨겨지며 원문은 저장하지 않습니다. `.env.local`에 무작위 세션 키와 scrypt 비밀번호 해시가 저장됩니다. 같은 명령으로 계정을 추가할 수 있습니다. 이 파일은 Git 제외 대상입니다.

`http://localhost:3000/login.html`에 접속합니다. HTML 직접 열기나 정적 서버 대신 이 서버를 이용하세요. 외부 의존성은 없습니다.

## Vercel 배포

기존 정적 배포에서 서버 권한 검사 방식으로 변경됐습니다.

| 설정 | 값 |
|---|---|
| Framework Preset | Other |
| Root Directory | `./` |
| Build Command | `npm run build` |
| Output Directory | `public` — 기존 `dist` 사용 금지 |
| Node.js | 24.x |

`vercel.json`에 빌드, 공개 출력 폴더, 함수 파일, 라우팅 설정이 들어 있습니다. 대시보드의 이전 Override는 해제하거나 위 값으로 맞춥니다.

Vercel **Settings → Environment Variables**에 `.env.local`의 다음 값을 추가하세요.

1. `AUTH_SECRET`: 생성된 문자열 전체.
2. `AUTH_ACCOUNTS_JSON`: 계정 JSON 배열 전체. 값을 감싸는 바깥 작은따옴표는 제외합니다.

Production과 필요한 Preview 환경에 설정한 뒤 **Redeploy**합니다. 계정 설정 변경 후에도 재배포가 필요합니다. 비밀번호 해시 및 세션 키를 코드, Git, 브라우저 JavaScript에 넣지 마세요.

공개 배포 파일은 로그인 관련 파일만 포함합니다. 보호된 페이지는 Vercel Function이 매 요청마다 세션과 역할을 검사한 뒤 반환합니다. 실제 데이터 파일 `dist/coach-data.js`는 함수 번들과 공개 배포에서 제외됩니다.

## 기능

코치 선택, 20분 단위 시간표, 레슨 등록, 예정 회차, 출석·불참, 예약 가능·불가 시간 설정, 브라우저 저장 및 초기화. 복잡한 기록은 원문 확인 대상으로 분리합니다. 출석은 예정 회차와 별개입니다.

## 데이터

Git에는 가상 시연 데이터 `dist/coach-data.sample.js`만 포함합니다. 실제 명단이 있는 `dist/coach-data.js`는 로컬에만 보관하며 인증 서버를 통해서도 제공하지 않습니다. 실제 데이터를 공개 저장소에 추가하지 마세요. 변경 내역은 계정별 브라우저 저장 공간에 보관하므로 다른 기기와 동기화되지 않습니다. 코치 역할은 모든 시연 코치 일정을 볼 수 있습니다. 개별 코치별 데이터 소유권 제한은 별도 기능입니다.

## 검증

```sh
npm test
npm run build
```

인증·권한·세션 만료·변조·직접 URL 접근·출처 검사 및 일정 데이터/이벤트 처리를 검사합니다. 실제 Vercel 배포 및 브라우저 시각 검증은 별도로 확인해야 합니다.

운영자가 환경변수로 계정을 관리하는 소규모 시연 방식입니다. 로그인 실패 제한은 함수 인스턴스 메모리에 적용되며 여러 인스턴스가 공유하지 않습니다. 대규모 운영에는 공유 로그인 제한, 관리형 인증 및 서버 데이터 저장이 필요합니다. 쿠키를 삭제해 로그아웃한 뒤에도 별도로 복제된 세션 토큰은 만료 또는 계정/키 변경 전까지 유효할 수 있습니다.
