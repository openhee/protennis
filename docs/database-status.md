## 원격 적용 이력과 로컬 파일

- `20261112002703_create_protennis_schema.sql`
- `20261112002943_restrict_rls_event_trigger_execution.sql`

CLI로 마이그레이션 파일을 생성한 뒤 MCP apply_migration으로 호스팅 DB에 적용했다. 원격에서 확정된 버전과 로컬 파일명을 맞췄다. `supabase/schema.sql`은 최초 스키마 SQL 참고본이며 추가 적용 대상으로 사용하지 않는다. 실제 재현은 `supabase/migrations`의 순서를 따른다.

Supabase CLI 버전별 명령을 확인하고 운영 DB에는 이미 적용된 SQL을 직접 다시 실행하지 않는다. 로컬 migration list와 원격 이력 비교는 프로젝트 연결 후 수행할 수 있다.

## 실행 검증

`supabase/tests/schema-smoke.sql`을 원격에서 실행하고 전체 롤백했다. 확인 항목:

- 같은 코치의 겹치는 수업/차단 불가, 인접한 20분 수업 허용.
- 같은 반복 규칙/발생일 재생성 불가, 같은 수업 참여자 중복 불가.
- 다른 지점 코치 연결 및 다른 회원의 수강권 사용 불가.
- 출석 변경 시 예정 회차 유지.
- 횟수 원장 수정 불가, 중복 차감/중복 복구 불가.
- 학생은 본인 명부·수강권·예약·수업만 조회.
- 코치는 담당 수업과 참여자 조회, 다른 회원의 전체 계약 조회 불가.
- 다른 지점 운영자의 예약 접근 불가.
- 일반 인증 계정의 역할 승격/직접 쓰기/원문 가져오기 테이블 접근 불가.
- 익명 계정의 회원 명부 조회 불가.

스키마 생성 직후 Supabase security advisor: lints 0건. 이후 Auth 계정 연결 후 재검사에서는 유출 비밀번호 보호 미활성화 WARN 1건이 반환됐다. 해당 기능은 Pro 이상에서 제공되며, 요금제나 Auth 설정은 변경하지 않았다. DB RLS 관련 경고는 없다.
Performance advisor는 아직 사용되지 않은 인덱스에 대한 INFO만 반환. 새 DB이므로 조회 부하가 생기기 전 필요한 제약/조회 인덱스를 삭제하지 않았다.

## 아직 구현하지 않은 범위

DB 구축 후 Supabase Auth 로그인 코드와 신홍경 코치 계정 연결을 추가했다. Vercel 환경변수 등록 및 새 코드 배포는 별도이며, 예약은 아직 localStorage에 저장한다. 로그인 상세는 `auth-setup.md`를 참고한다.

- 추가 회원·코치·가격표·수강권의 검토된 실제 데이터 등록. 신홍경 코치 1명은 로그인 연결을 위해 등록했다.
- 예약/변경/출석/취소 API와 원장 처리를 하나로 묶는 트랜잭션.
- 마지막 자리/쿠폰 동시 요청 제어와 레슨생 시간 중복 검사. 코치 시간 EXCLUDE 외의 업무 동시성은 아직 검증하지 않았다.
- 상품·수강권 적합성, 정원/쿠폰 보유 횟수/open window 검증, 보강·휴강 정책 적용.
- 3·4주차 생성 및 중복 요청 본문 검증. 발생일 UNIQUE 제약만 적용된 상태다.
- 레슨생용 개인정보 없는 예약 가능 시간 API, 코치별 화면 필터링.
- 원장 refund 금액·원본 소비의 의미 검증은 후속 트랜잭션에서 처리해야 한다. 현재는 동일 수강권 FK/단일 복구/부호 등 구조 제약만 적용됐다.

따라서 아직 클라이언트 직접 쓰기 권한을 열거나 서버 비밀키를 화면에 제공하면 안 된다. 예약 API를 구현할 때 위 업무 제약을 완성하고 동시성 테스트를 추가한다.
